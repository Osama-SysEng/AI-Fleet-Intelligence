# تشغيل AI Fleet Intelligence في وضع المحاكاة

النسخة المحسنة تقبل telemetry محاكى بعد تحقق صارم من الهوية والتسلسل والوقت والإحداثيات والمدى. تحفظ الواجهة إحداثيات مقربة إلى منزلتين عشريتين لخفض دقة التتبع في العرض. تصنف السياسة الإشارات إلى `normal` و`watch` و`critical`، لكنها تعيد **توصية مراجعة** فقط.

| المجال | الوضع الحالي | شرط أي ربط مستقبلي |
|---|---|---|
| بيانات الموقع | محاكاة مع إخفاء دقة الموقع في event. | موافقة قانونية، تقليل البيانات، retention، وRBAC. |
| تنبيهات السائق | لا توجد رسائل. | سياسة موافقة، قناة معتمدة، مسودة ومشرف، وسجل تسليم. |
| أوامر المركبة | API يعيد رفضًا صريحًا. | لا تدمج أبدًا في لوحة التحليلات؛ يلزم نظام OEM معتمد وتقييم سلامة. |
| التنبؤ بالصيانة | إشارات قابلة للتفسير فقط. | بيانات صيانة حقيقية، مراجعة فني، وقياس دقة النموذج. |
| التخزين | في الذاكرة لغرض الاختبار. | قاعدة بيانات مدارة وتشفير وفصل المستأجرين. |

> لا يصح استخدام هذه التحليلات وحدها لمخالفة سائق أو اتخاذ قرار توظيف أو منع قيادة أو تنفيذ تحكم بالمركبة. فهي مؤشرات تشغيلية تحتاج مراجعة بشرية وسياقًا موثقًا.

## تحديث الإصدار

أضيفت نماذج مركبات وسائقين صارمة، محرك مخالفات تفسيري لسرعة/وقود/حرارة المحرك، مخطط PostgreSQL للـtelemetry والمخالفات مع uniqueness لمنع التكرار، وموصل Telegram محاكاة فقط. كما أضيف Docker Compose محلي مع شبكة داخلية، PostgreSQL غير منشور خارجيًا، تشغيل Backend كمستخدم غير root، وإسقاط capabilities.

قبل التشغيل، انسخ `backend/.env.example` إلى `backend/.env` وغيّر كلمة المرور والرمز. شغّل `docker compose --env-file backend/.env -f docker/docker-compose.yml up --build`. اختبر محليًا عبر `PYTHONPATH=. python3 -m unittest discover -s backend/tests -p 'test_*.py'`.

لا تُرسل هذه النسخة أوامر للمركبات ولا تنفذ Telegram أو Dispatch حقيقيًا. أي تفعيل مستقبلي يتطلب موصلًا منفصلًا، اعتمادًا وموافقة، TLS، RBAC، rate limiting، audit trail، staging، واختبار إيقاف آمن.
